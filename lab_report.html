Lab Project Report: Parameterized Cache Simulator in C++

1. OOP Design & Menu State Management

The Parameterized Cache Simulator is architected using clean Object-Oriented Programming (OOP) principles in C++17, decoupling the underlying simulation hardware model (CacheCore) from the user interface and state rendering engine (main.cpp).

Key Classes & Abstractions:

  • CacheLine: Encapsulates valid bit ($V$), 64-bit tag, last access timestamp (for LRU), and insertion timestamp (for FIFO).
  • CacheSet: Contains a vector of $N$ CacheLine instances representing associative ways.
  • CacheCore: Manages global cache parameters (Cache Size, Block Size, Associativity, Replacement Policy), bitwise address decomposition masks, and simulation step access logic.

Menu State Management Workflow:

  1. Configuration Validation: Enforces power-of-2 constraints ($\text{Size} > 0$ and $(\text{val} \& (\text{val}-1)) == 0$). If unconfigured, action buttons display: Error: Please configure cache parameters first.
  2. Trace Validation: Ensures parsed memory instructions exist in buffer. If empty, action buttons display: Error: Please load a trace file first.
  3. Execution State Transition: Steps incrementally increment current_step pointer, update real-time statistics dashboard, append step records to execution log, and trigger active set/way cell highlighting on the cache visualizer matrix.

3. Architectural Analysis: Why Hit Rate Increases with Associativity

In a Direct-Mapped Cache (1-Way), each memory block maps strictly to a single set index ($Index = (Address \gg Offset) \& (Sets - 1)$). When multiple addresses (such as 0x1000, 0x2000, 0x3000, and 0x4000) share the exact same set index, severe Conflict Misses (Thrashing) occur because each incoming block immediately evicts the previously loaded line, even though total cache storage remains underutilized.

As associativity increases to 2-Way and 4-Way Set Associative, multiple cache ways ($N$) become available within each set. This allows concurrently active memory blocks to reside simultaneously within the set without kicking each other out. Consequently, temporal locality is preserved for addresses like 0x1000 and 0x1004, drastically reducing conflict evictions (from 12 evictions down to 5) and increasing the overall Hit Rate from 7.14% to 35.71%.
